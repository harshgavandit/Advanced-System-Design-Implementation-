# Phase 0: Contracts, Fixtures, and Baseline Implementation Plan

Goal: freeze the current API surface, generate deterministic data, execute real HTTP contract checks, and record a populated-data baseline before Phase 1 fixes.

Spec: `../specs/2026-10-06-production-grade-scaling-design.md`, Phase 0.

Authorization: the user requested implementation of each phase in sequence. Execute this phase inline, including isolated test-data setup and test-owned process lifecycle. Preserve all existing application data and services.

## Decisions

- Work on `codex/phase-0-contract-baseline` in the existing D: checkout. Avoid a managed worktree whose placement could violate the D:-only requirement; no application source changes are required for this foundation.
- Capture `/products` baseline behavior as contract version 0.1.0. Do not silently replace it with the incompatible `/items` scoped-rule description.
- Keep known production defects in a separate report. A compatibility test passing does not certify production readiness.
- Use only installed Express dependencies and Node built-ins. Use k6 for load testing.
- Test writes target only a dedicated loopback Mongo instance on port 28027 and the exact database `phase0_contract_test`. Never use `.env` values or reset existing databases.

## Tasks

1. Add deterministic fixture and target-guard tests. Verify initial failure, implement generator/manifest and target allowlist, then verify deterministic hashes and boundary rejection.
2. Add OpenAPI baseline, five-implementation capability matrix, and schema/operation validation tests. Missing operations must be reported unsupported, not successful.
3. Add an isolated Express HTTP runner using the real app and MongoDB. Cover all advertised business operations, response shapes, user ownership, pagination, validation, refresh/logout, and metrics. Keep known defects observable in a separate gap list.
4. Add a guarded test launcher and k6 populated baseline. Record source hash, tool/runtime versions, fixture hash, workload, process resource observations, and limits. Stop only test-owned resources.
5. Run all foundation tests, existing Express tests/typecheck/build, real HTTP checks, and k6. Review the resulting files and write `docs/evidence/phase-0-baseline.md` with exact results and remaining gaps.

## Review focus

- Unsafe database URI, unexpected database name, nonempty target, and URI option bypasses.
- Nondeterministic timestamps/identifiers and inconsistent fixture manifests.
- OpenAPI operation names that are missing from capability declarations or vice versa.
- Skipped unsupported Go routes presented as passed parity.
- HTTP status-only tests that miss incorrect bodies, cross-user access, or failed persistence.
- Live-user data, tokens, and secrets leaking into evidence artifacts.
